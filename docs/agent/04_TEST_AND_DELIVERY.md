# 阶段四：自动化测试、文档与交付（预计 1 天）

## 开始前
完整阅读 `docs/agent/00_PROJECT_RULES.md`、`03_TASKS.md`、`docs/agent/PROGRESS.md`，检查整个项目现状。以稳定和交付为目标，不擅自新增功能。

## 目标
使项目可以被他人克隆、配置、迁移、运行、测试和演示；形成可用于实习简历与面试的可验证成果。

## 实现任务
1. 审查项目结构、依赖、配置、安全边界、数据库事务、时间处理和异常响应；修复明显缺陷，不大规模重构。
2. 完善 `tests/conftest.py` 和认证/任务测试。通过 FastAPI dependency_overrides 注入隔离测试 Session；可使用 SQLite 临时数据库，注意 StaticPool/线程及 SQLite 外键设置；测试中不接触真实 MySQL 开发库。必要时提供 MySQL 集成测试的可选方案。
3. 至少覆盖：健康检查；注册与重复注册；登录成功/失败；无效/过期 Token；获取当前用户；任务 CRUD；分页/筛选；非法输入；未认证访问；跨用户读取、修改、删除、列表隔离。
4. 执行 `pytest -q`，报告真实的通过数、失败数、未运行项；如有问题，修复后重新执行。可选运行编译检查。
5. 检查 Alembic 可从空 MySQL 数据库升级到 head；若环境没有 MySQL，明确记录未验证，不可声称已通过。
6. 完善 README：项目简介、功能、技术栈、目录结构、MySQL 创建及 `.env` 配置、依赖安装、迁移、启动、`/docs` 演示、测试命令、典型 API 调用顺序、已知限制、未来扩展。
7. 提供 `.env.example`、`.gitignore`；确保无真实密码、JWT Secret、Token 或数据库凭据提交。
8. 生成 `docs/agent/ACCEPTANCE.md`：逐项记录验收结果、执行命令、环境限制、失败项及解决情况。
9. 生成 `docs/agent/INTERVIEW_NOTES.md`：系统请求链路、JWT 认证链路、同步 def + SQLAlchemy 选择、Session 生命周期、事务、权限隔离、分页、Alembic、测试策略，以及 3 个真实可复述的技术难点。只能写实际实现的内容。

## 验收
- README 的本地运行步骤可复现（环境具备时实际验证）。
- Swagger 文档列出所有契约 API，可完成注册→登录→授权→创建任务→查询→更新→删除演示。
- 核心自动化测试真实通过；跨用户访问安全测试通过。
- 正式数据库使用 Alembic 迁移，不在启动时自动建表。
- 项目没有引入总控禁止的技术，也没有泄露密钥。
- 交付报告区分“已通过”“失败”“未验证”，不夸大成果。

## 阶段结束交接
更新 `docs/agent/PROGRESS.md`，附上最终验收报告位置、测试结果、启动步骤、遗留问题、可选 V2 扩展清单（团队空间、Redis 缓存、Docker、Agent 自然语言任务创建；仅建议，不实现）。
